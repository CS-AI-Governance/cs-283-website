{%- comment -%} One thematic unit of the course calendar: a header row spanning the table, then one row per entry. Structure adapted from Just the Class (github.com/kevinlin1/just-the-class, MIT); re-implemented as a table. Rows are declared in the module's front matter and reference lectures by number — the date, title and URL come from the _2026 collection, so the schedule and the lecture pages cannot disagree. Row kinds: - lecture: N a lecture, looked up in site['2026'] - section: true the weekly Thu/Fri section - note: "…" a one-off (fall break) A unit spans as many calendar weeks as its lectures need, so rows are simply listed in date order and `section: true` goes wherever that week's section falls. {%- endcomment -%} {{ page.title }} {%- for row in page.rows -%} {%- if row.lecture -%} {%- assign doc = site['2026'] | where: 'lecture', row.lecture | first -%} {%- if doc -%} {{ doc.date | date: '%a, %b %-d' }} {%- comment -%} The wrapper span is the flex container that keeps the number centred against a wrapped title; see .cal-topic-inner. {%- endcomment -%} {{ doc.lecture }} {{ doc.title }} {%- if doc.slides -%} [slides] {%- else -%} [slides] {%- endif -%} {%- comment -%} An entry may set `track: law`, which adds .label-due--law so the law-student deadlines read in a darker red than the shared ones. `deadlines` is a list so one lecture can carry more than one badge (L19 closes both the final project and the law paper). Each entry's date is a separate key so only it can be bolded inside the badge; the label stays regular weight. {%- endcomment -%} {%- for d in doc.deadlines %}{{ d.label }}{% if d.date %} {{ d.date }}{% endif %}{% endfor -%} {%- endif -%} {%- elsif row.section -%} Thu/Fri Section{{ row.topic }} {%- elsif row.note -%} {{ row.note }} {%- endif -%} {%- endfor -%}
